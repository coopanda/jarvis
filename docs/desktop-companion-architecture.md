# Permissioned Desktop Companion / Local File and Photo Bridge

Status: architecture specification only. No daemon, pairing, local device access, credential connection, OS execution or photo upload is implemented by this document. Roblox is roadmap-only.

## Trust boundaries
The browser HUD and Render app cannot directly inspect the owner's machine. An opt-in local companion runs with ordinary user privileges, binds to loopback only, and opens an outbound TLS connection to the cloud. No public local listener, arbitrary shell execution, plugin installation, elevation, unrestricted filesystem scan or silent background observation is permitted. File/photo permissions default OFF independently from companion connectivity.

## Pairing protocol
The owner initiates pairing from an authenticated browser session. The local app displays the cloud origin, device name and a short verification phrase for explicit approval on both sides. Device identity is generated locally and private material remains in the OS secure store; the cloud stores only public device identity and revocation metadata. Do not copy credentials into chat, workspace files, logs or documents. Pairing expires after five minutes and is single-use. Device connections use mutually authenticated, outbound TLS WebSocket messages with a monotonic sequence, unique request ID, expiry and signed payload digest. Reject wrong origin/device, stale sequence, replay, changed payload or unpaired device. Disconnecting revokes the device and cancels queued commands; reconnection does not restore grants.

## Capability and approval model
Connectivity is never permission. Require persisted cloud Permissions & Connections toggles AND local OS consent AND a scoped local grant. Separate grants: file.search, file.read, file.write, file.delete, photo.search, photo.preview, photo.upload, screen.capture, app.open and window.move. Search/read grants identify chosen roots, file types, byte limits and expiry. A read grant does not permit upload; photo search does not permit opening originals. Every upload, overwrite, deletion, external message or workflow execution needs exact owner approval of the canonical payload digest, destination, selected files and cost. Never approve inferred commands or an entire unbounded directory. Deny capability identifiers not in the allowlist.

## Local file and photo access
Use the OS folder picker for roots and bookmark permissions on supported systems. Revalidate real paths and ancestor symlinks for every operation; deny traversal, symlink escapes, hidden/system/credential directories, network mounts and device files. Treat filenames, EXIF, OCR and document content as untrusted input, not instructions. Limit search results, bytes, concurrency and execution time. macOS Spotlight may return indexed metadata within approved roots only; it is not an authorization boundary. On other systems use an equivalent bounded root-local index. For photo libraries prefer an OS photo picker with selected assets; directory scanning requires a separate photo root grant. Create local thumbnails with metadata stripped. Never send full photos or EXIF/location data by default.

## API and data contract (proposed, not implemented)
POST /api/companion/pair/start and /confirm require the owner session, same-origin checks and companion permission. GET /api/companion/devices returns redacted device identity, last-seen time and local grants. POST /api/companion/jobs/prepare creates an expiring review record with device ID, operation, canonical scoped arguments, digest and size/cost estimate. POST /approve revalidates permissions and exact digest immediately before dispatch. POST /cancel and /revoke are always available to the owner. The outbound device channel accepts typed commands only; unknown operations fail closed. Results include request ID, observed time, bounded output and receipt state: review, queued, dispatching, receipt, failed, cancelled or unknown. A dispatch timeout is unknown, not retry-safe success or failure. Reconcile before any retry.

## Revoke, stop and persistence
Recheck cloud and local grants immediately before each file read and network transfer, not only at preparation. OFF stops active streams, closes file handles, aborts uploads and cancels undispatched jobs. Already sent data cannot be recalled; report that honestly. Emergency stop persists a halt requiring explicit resume; restart marks in-flight external outcomes unknown. Persist settings, scoped grant metadata and redacted audit receipts in configured durable storage; ephemeral Render Free disk cannot establish restart durability. Retain no file contents or thumbnails in cloud unless separately approved, and provide deletion/retention controls. OAuth credentials are not workspace memory.

## Required implementation and acceptance tests
Implement and test the local daemon, authenticated pairing, device lifecycle, typed command validator and UI before claiming a connected companion. Test defaults OFF, unpaired rejection, owner authentication, expiry, replay, digest mismatch, cross-device requests, revoke during transfer, root/symlink traversal, hidden credential exclusions, file quotas, metadata stripping, photo picker isolation, separate upload approval, restart durability and unknown-outcome reconciliation. Run syntax, unit and startup tests without production credentials. Test the same deployed build hash shown by /health. No silent OS permission escalation; no arbitrary shell bridge.
